💡 핵심 기획 의사결정 기록
1

생기부 업로드 방식: 파일 업로드 vs 텍스트 붙여넣기

텍스트 복사 시 서식/표 구조가 깨지는 문제 → 파일 업로드(Excel/PDF)가 데이터 정합성 우수

결정: 파일 업로드 방식 채택, 추후 텍스트 입력 보조 옵션 추가 검토
2

면접 연습 UI: 채팅형 vs 화상 면접형

MVP 단계에서 화상은 기술 복잡도 높고, 사용자 진입 장벽 상승 → 채팅형 우선 출시

결정: 텍스트 채팅형 우선, 음성 모드 2차 출시, 화상은 v2 검토
3

AI 모델: GPT-4 vs Claude

한국어 생기부 분석 정확도 비교 테스트 진행 → Claude가 교육 도메인에서 더 안정적 성능

결정: Claude API 채택, 프롬프트 최적화로 비용 효율성 확보
4

질문 유형 분류: 단일 vs 다중 카테고리

면접 유형별(종합/교과/학교자체) 차별화된 질문 생성이 사용자 만족도에 직결

결정: 3개 유형 × 3개 난이도 = 9가지 조합으로 질문 생성
5

인증 방식: 소셜 로그인 vs 이메일 인증

미성년자 대상 서비스라 소셜 로그인 동의 절차 복잡 → 이메일 인증으로 단순화

결정: 이메일 인증 코드 방식, 추후 카카오 로그인 추가 예정
6

평가 기준: 범용 vs 면접 유형 특화

교대 면접(교직적성), 일반 대학(전공적합성) 등 면접 유형마다 평가 기준이 다름

결정: 인성 + 전공적합성 + 교직적성 3축 평가, 유형별 가중치 차등 적용

테스트 가이드

HIGH-LOG 서비스를 로컬에서 실행하고 테스트하는 방법입니다.

💻 로컬 개발 서버 실행
1
저장소 클론
git clone <repository-url>
cd highlog
2
의존성 설치
npm install
3
환경변수 설정
프로젝트 루트에 .env 파일을 생성합니다.
# .env
VITE_API_URL=https://onedaypocket.shop
4
개발 서버 시작
npm run dev
# http://localhost:5173 에서 확인
🧪 주요 테스트 시나리오
ℹ️ 테스트 전 회원가입이 필요합니다. 유효한 이메일로 가입 후 이메일 인증을 완료해주세요.
회원가입 / 로그인
1
이메일 회원가입 → 인증코드 입력 → 가입완료
2
로그인 → "로그인 유지" 체크 → 브라우저 새로고침 후 세션 유지 확인
3
비밀번호 찾기 → 인증코드 → 새 비밀번호 설정
생기부 업로드 & 질문 생성
4
생기부 파일 업로드 → 상세조회 → AI 질문 생성
5
생성된 질문 목록 확인 (종합/교과/학교자체 유형, 난이도별 필터)
6
질문 즐겨찾기 추가/제거
면접 연습
7
텍스트 면접 연습 시작 → 답변 입력 → AI 피드백 확인
8
연습 결과 점수 확인 (인성/전공적합성/교직적성)
9
연습 이력 조회 및 이전 결과 확인
